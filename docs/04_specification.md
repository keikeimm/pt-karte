## 2. カルテテンプレート仕様

### 2.1 共通仕様

- 全テンプレートは `role`付き（`counseling`/`precautions`）か、role無し（`karte`）のいずれか
- role無しテンプレートのチャートは `date`（記入日、YYYY-MM-DD）で管理され、
  `title`は持たない（`null`）
- role付きテンプレートのチャートは `title`をテンプレ名で固定し、`date`は`null`
- `skipHeaderPage: true` を持つテンプレート（`precautions`）以外は、先頭に
  「顧客データ」ページが自動付与される（`instantiatePages()`）。このページは
  クライアント基本情報のサマリー（`_clientSummary`）と担当者メモ欄を持つ

### 2.2 counseling（初回カウンセリングシート）

| ページ | kind | 主なフィールド |
| --- | --- | --- |
| 顧客データ（自動付与） | form | 顧客サマリー、担当者メモ |
| 目標・要望 | form | 主な目標、目標時期、なりたい姿、不安・懸念 |
| 生活習慣 | form | 職業、起床/就寝、睡眠時間、喫煙、飲酒、ストレス、活動量 |
| 食事習慣 | form | 食事回数、外食頻度、自炊、間食、水分量、アレルギー、サプリ |
| 運動・スポーツ歴 | form | 競技歴、現在の運動習慣、トレーニング経験 |
| 医学スクリーニング（PAR-Q+） | form | 定型7問（yesno）＋服薬・既往歴・血圧・補足 |
| 整形外科的既往・痛み | canvas（背景: 人体図前面） | 痛み・違和感のメモ |

### 2.3 precautions（注意事項・免責同意書）

`skipHeaderPage: true`（顧客データページ無し。緊急連絡先はクライアント基本情報に
統合済みのため、このテンプレートは持たない）

| ページ | kind | 主なフィールド |
| --- | --- | --- |
| 運動参加の注意事項 | form（スキップ不可） | 定型注意文（表示のみ）＋「読み理解した」チェック |
| 免責・キャンセルポリシー | form（スキップ不可） | 定型文（表示のみ）＋同意チェック、記入日、本人署名（手書き） |

### 2.4 karte（カルテ）

| ページ | kind | 主なフィールド |
| --- | --- | --- |
| 顧客データ（自動付与） | form | 顧客サマリー、担当者メモ |
| 本日の記録（スキップ不可） | form | 体調（select）、睡眠時間、体重、体脂肪率、メモ |
| メニュー・測定記録 | form | テーブル（種目・項目／重量・数値／回数・セット／メモ、初期6行、行の追加・削除可） |
| 白紙（手書き・自由記述） | canvas | 手書き（背景に人体図/姿勢図を選択可）＋自由記述メモ |

## 3. 会員ID採番仕様

- 形式: `M` + 5桁ゼロ埋め連番（例: `M00001`, `M00002`, …）
- 採番ロジック（`store.js` `nextMemberId()`）: 既存の全クライアントの`memberId`から
  数字部分を抽出し、最大値+1を採番する。既存クライアントが0件なら`M00001`
- 採番タイミング: クライアント新規作成の保存直前（`app.js` `addClient()`内で
  `nextMemberId()`を呼び、`saveClient`前に`c.memberId`へ設定）
- 手動編集は不可（編集フォームに入力欄を出さず、保存済みの値を表示のみ）
- 欠番・再利用は考慮しない（削除しても番号は詰め直さない）

## 4. カルテの記入日・保存仕様

### 4.1 記入日を選んでの作成

- クライアント詳細「＋ カルテを作成」を押すとモーダルが開き、記入日（`<input type=date>`、
  デフォルトは本日）を選んで「作成」を押す
- 作成前に `store.js` `isKarteDateTaken(clientId, date)` で、同じクライアントの
  他の`karte`チャートが既にその日付を使っていないか確認する
- 重複していれば `<日付> のカルテは既に作成されています` とトースト表示し、
  モーダルは閉じない（作成されない）
- 重複していなければ `createChart(clientId, 'karte', date)` で作成し、
  エディタへ遷移する
- 日付未選択（空文字）では「記入日を選んでください」とトースト表示し作成しない

### 4.2 明示的な保存とその場での記入日変更

- カウンセリングシート・注意書き・カルテのいずれのエディタにも、画面上部
  （クラム部分）に**保存**ボタンが常時表示される
- フォーム入力・手書き・ページのスキップ設定など、あらゆる編集操作は
  メモリ上の値を更新し「未保存の変更があります」の表示に切り替えるだけで、
  **保存ボタンを押すまでIndexedDBには書き込まれない**
- 保存ボタン押下時（`karte`のみ）: 記入日が他のカルテと重複していないか
  再度 `isKarteDateTaken(clientId, date, excludeChartId=自分自身)` で確認する。
  重複していれば `記入日 <日付> のカルテは既に存在します。日付を変更してください。`
  とトースト表示し、保存されない（「未保存の変更があります」表示は継続）
- 重複が無ければ `saveChart()` を呼び、保存タグが「保存済み」に変わり
  「保存しました」とトースト表示する
- `karte`の記入日は編集画面内の日付入力でいつでも変更できる（変更しただけでは
  保存されず、保存ボタンを押すまでは上記の重複チェック含め確定しない）

### 4.3 保存せずに画面を離れようとした場合

- 未保存の変更がある状態でハッシュが変わろうとする（「← 戻る」リンク、
  ブラウザの戻る/進む、他のクライアントへの直接遷移など、経路によらず全て）と、
  `保存されていない変更があります。保存せずに移動すると変更内容は失われます。
  移動しますか？` の確認ダイアログが出る
  - 「OK」（移動する）を選ぶと、保存されないままその画面へ遷移する
    （メモリ上の変更は破棄される）
  - 「キャンセル」を選ぶと画面遷移は取り消され、編集中の内容を保持したまま
    エディタに留まる（再読み込みはしない）
- タブを閉じる・ページを再読み込みする場合も、未保存の変更があればブラウザ標準の
  離脱確認ダイアログが出る（`beforeunload`）

## 6. Excel（.xlsx）書き出し仕様

- 対象: クライアント詳細画面「このクライアントを書き出す（Excel）」
- 実装: `js/export.js` `exportClientXlsx()`。生成には `js/vendor/xlsx.core.min.js`
  （SheetJS）のグローバル`XLSX`を使用
- ファイル名: `karte_<氏名を安全化した文字列>_<YYYY-MM-DDTHH-mm>.xlsx`
  （氏名は`\p{L}\p{N}_-`以外を`_`に置換し40文字に切り詰め）
- シート構成（固定4シート、この順）:

| シート名 | 内容 | 無い場合 |
| --- | --- | --- |
| 基本情報 | クライアントの全基本情報項目（会員ID・氏名〜備考、緊急連絡先・かかりつけ医を含む）を「項目/内容」の2列で列挙 | - |
| カウンセリングシート | `role='counseling'`のチャート1件分。ページ名を見出しに、各フィールドのラベル/値を列挙 | 「カウンセリングシートは未作成です。」の1行 |
| 同意書 | `role='precautions'`のチャート1件分。同上 | 「同意書は未作成です。」の1行 |
| カルテ | `role`無しの全チャートを記入日の古い順に列挙。チャートごとに「記入日: YYYY-MM-DD」を見出しとして区切る | 「カルテはまだありません。」の1行 |

- フィールド種別ごとの出力ルール（`pageValueRows()`）:
  - `heading`/`static`: 出力しない（見出し・定型文はExcel上では省略）
  - `table`: ラベル行→列見出し行→各データ行の順で展開
  - `sign`: ストロークが1本以上あれば「署名あり」、無ければ「未署名」
  - `checkbox`: `true`→「はい」、`false`→「いいえ」
  - `note`ページの本文: 「メモ」行として1行追加
  - `canvas`ページの手書き: ストロークがあれば「あり（アプリ内で参照）」、
    無ければ「なし」（手書き画像そのものはExcelに埋め込まない）
  - 「顧客データ」ページは基本情報シートと重複するため出力しない

- **数式インジェクション対策**: 上記いずれの値も文字列として書き出す直前に
  `sanitizeCell()`を通す。値が `=` `+` `-` `@` またはタブ/CRで始まる場合、
  先頭に `'`（アポストロフィ）を付与してから書き込む。これによりExcel等で
  開いた際に数式として評価されることを防ぐ（詳細は非機能要件定義書 §3）。
  副作用として、該当する値はExcel上で先頭に `'` が付いて見える

## 7. JSONバックアップ仕様

- 対象: クライアント一覧「バックアップ」→「全データを書き出す」／「JSONを読み込む」
- 実装: `js/export.js` `exportAll()` / `importFile()`
- フォーマット:
  ```json
  {
    "format": "pt-karte-backup",
    "version": 1,
    "kind": "all",
    "exportedAt": "ISO8601文字列",
    "clients": [ /* clients ストアの全レコード */ ],
    "charts": [ /* charts ストアの全レコード */ ]
  }
  ```
- 読み込み時の検証: `format`が`"pt-karte-backup"`以外、または`kind`が`"all"`以外は
  例外（それぞれ「対応していないファイル形式です」「不明なバックアップ種別です」）
- 読み込みモード:
  - マージ: 既存データはそのままに、読み込んだ`clients`/`charts`を`id`で upsert
  - 全置換: 読み込み前に`clients`/`charts`ストアを`clear`してから upsert
- ファイル名: `karte_backup_<YYYY-MM-DDTHH-mm>.json`
- この形式はアプリ自身の復元専用。Excelファイルはこの形式では**読み込めない**
